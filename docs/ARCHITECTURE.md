# 架构与可信边界

`:core` 是纯 Kotlin/JVM 模块，与 Android、SQLite 和模型隔离。`World` 为不可变可信状态；`Rules.apply(world, command, expectedRevision)` 在校验后返回新的世界和一条追踪记录，拒绝旧版本号。经济、人物、事件和记忆过滤分别由独立对象负责。随机顺序只依赖世界种子、当前季度和模板 ID，不引用系统时间。

`:app` 通过 `GameViewModel` 的互斥门串行执行。SQLite `saves` 和 `history` 在同一个事务内提交；每槽位版本比较加 `(slot, revision)` 唯一键防重复结算。状态保存完成后才调用模型。进程意外退出最多丢失未确认预览或未完成的辅助叙述，不回滚已提交世界。新建及导入只使用空槽，不覆盖原游戏。

玩家交互使用可暂停的连续时间，1×/4×/16×/64×；90 日仅为后台财政记账周期。`RealtimeEngine` 为前台入口，负责预留资金、最多三项并行排程、办理完成的重新验证，以及取消退款。`Rules.apply(..., advanceDays=false)` 执行效果，时钟由独立入口推进。纯 Kotlin 兼容结算入口保留用于长程回放测试，不作为 UI 回合操作。巡游有旅行进度、地区位置、身份、风险、随从、摄政与停留预算。地方行动按日计时，越过季度边界运行国政引擎。证据真伪为引擎事实；AI 提示只包含可见名称而不泄露真伪字段。定罪需真实证据总分至少 70 且具有原始账册；重复线索不重复累积，结案不可重复追缴。身份自述不会变成印信验认。

33 个事件都具有因果谓词、季度冷却与数值效果，每季最多两项。在建项目消耗资金并等待 2–3 季，研发需要经常预算，军备与道路产生维护支出。财政赤字受信用上限限制，不能循环无成本借款。

AI 适配为 `ModelManager` + JNI `NativeBridge`，底层 llama.cpp b5046。规则输出是权威，AI 输出只用于 UI 演绎。JSON 使用严格 kotlinx.serialization 解码和允许的政策类型集，随后重复走规则验证。原生模型/上下文由互斥锁管理，取消标志与截止时间在每次 decode 中生效。默认线程不超设备 CPU 数；可用内存低于模型文件大小 + 350 MiB 时拒绝加载；压力回调允许卸载。该估算不是手机峰值内存认证。

所有模型下载仅向公开官方模型库发起，不携带存档内容。存档导入导出使用 Android SAF，应用不要求电脑。模型首次加载不自动下载任何大文件。GGUF 头校验、长度校验与文件哈希完成后才调用 native；导入文件的格式头并不能证明所有架构兼容，native 加载失败会降级。

## 后续

P1 验收尚需 ARM64/vivo Android 16 真机中文叙述与命令理解评估、加载时间/内存/速度/连续推理测量。P2 扩展地方案件、腐败分类、长期人物关系、摄政授权、外交冲突与经济平衡。现有测试与实际验证边界见交付报告。


连续时间的存档每次提交仍做版本比较。普通时钟变更只更新可信状态，不写一条无意义的历史；到达、竣工、分娩、政策完成和季度结算才形成档案。AI 按最近的重要事件版本过滤结果，纯时钟更新不会持续丢弃叙述。后台停止时间，不按真实离线时长追赶。

地图使用独立 WorldMapScreen、MapSnapshotMapper 与 MapDeltaDispatcher。地图JS只读取地图表示并发送稳定ID选择，原生规则校验、SQLite提交完成后再发版本更新。原HTML编辑能力位于不影响游戏状态的沙盘。详见 MAP_V4_INTEGRATION.md。
